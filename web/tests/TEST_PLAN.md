# v1 test plan

Scope: the in-browser volleyball skeleton app in `web/` (plan `07_architecture_plan.md`, acceptance in §6). This file
is the single index from every acceptance criterion to a command or a manual step. ML output is never 100 % right, so
every ML criterion is a measured threshold against a named reference, and the reference's bias is stated.

## 1. Levels and owners

| Level | Runner and command | Where | What it proves | Owner |
|---|---|---|---|---|
| unit | vitest `unit`, Node: `npm test` | `src/**/*.test.ts`, `tests/unit/**` | pure logic: contracts, tracker, smoothing, metrics, codecs | module owner; cross-module in `tests/unit` is the tester's |
| dom | vitest `dom`, happy-dom: `npm test` | `*.dom.test.ts(x)` | component behaviour without a GPU | UI |
| browser | vitest `browser`, Chrome for Testing, real WebGPU: `npm run test:browser` | `src/**/*.browser.test.ts` | WGSL parity, ORT sessions, WebCodecs | ML, backend |
| harness | vitest `harness`, Node, long runs: `npm run test:harness` | `*.harness.ts`, `tests/harness/` | accuracy, tracking, ball and jitter numbers against references | tester (scoring), ML (engine runs) |
| e2e | Playwright: `npm run test:e2e` | `tests/e2e/` | the whole app in a browser, mock or real engine | tester |
| cross-browser | Playwright WebKit and Firefox: `npx playwright test -c tests/playwright.cross.config.ts` | `tests/e2e/` (tagged) | M3 browser matrix | tester |
| manual | checklist in §8 | real devices | iPhone, Android, Windows, Safari, Dolby Vision | lead, owner of the devices |

Gates for every task of every persona: `npm run typecheck && npm run lint && npm test`. Higher levels are run when the
task touches them. Tests are written next to the behaviour they check; cross-module scenarios live in `tests/`.

| Id | Browser | Mode | WebGPU adapter | Used for |

`PLAYWRIGHT_BROWSERS_PATH=<scratch>/pw-browsers npx playwright install firefox webkit` (the probe README has the

a visible "skipped: binary not installed" annotation instead of passing silently. Playwright WebKit and Firefox are
not release Safari and Firefox: codec rows are confirmed manually (§8).

Scratchpad is temporary: if gone, the reference is the ML persona's first Node run |
| tracking labels | `tests/fixtures/tracks.json` (`node tests/tools/make-tracks.ts`; review ops in `tracks.overrides.json`) | identities on the gtu, px330, beach 60-frame runs (2 s each): teacher person boxes, IoU linker with gap stitching, flicker (< 5 frames) turned into ignore regions, then review in `tests/tools/label.html` (`npm run dev`, open `/tests/tools/label.html`). Score a tracker with `node tests/tools/score-tracks.ts <predictions.json>` |
| ball labels | `tests/fixtures/ball.json` (hand-reviewed, not regenerated; review/extend in `tests/tools/ball-label.html`) | 160 frames on clips other than gtu (VballNet was trained on gtu, so gtu numbers are never acceptance): 140 with the ball visible (centre + radius) and 20 explicitly absent, keyed by PTS microseconds; unlisted frames are unlabelled and never scored. Provenance: beach and the pexels/attempt frames are D-FINE-S `sports ball` proposals that I accepted or rejected from crop montages (centre = box centre); the 28 px330 frames where the detector misses the ball were localised by a colour mask and checked on montages. Bias: the visible set leans to balls a detector can see; hard small balls (attempt_03 dark ball, wide beach) are mostly unlabelled. Hit rule: 9 px at 1920 px width scaled to the frame (`strict`), or within 40 % of the labelled radius for large blurred close-up balls (`size-aware`). Pixel tolerances are in display-space pixels scaled by frame width (ball hit = within 9 px at 1920 px width). All
timing keys are PTS in integer microseconds; no test derives a frame from `t * fps`.

## 6. Flake policy

- No retries in CI config by default (`retries: 0`); a failure is investigated, not re-run until green.
- Timing assertions use a budget measured over many samples (p95 or median), never a single sample, and live in the perf
  suite so functional suites never fail on speed.
- One automatic re-run is allowed only for suites tagged `@gpu-timing`, and the run is reported as "passed on retry".
- A test that flaked twice is quarantined with `test.fixme('flaky: <issue>')` and an owner; quarantined tests are
  listed in the weekly acceptance report.
- Waits are on observable state (`window.__engine` counters, `data-testid` text, `waitForFunction`), not fixed sleeps.
- Accuracy thresholds are set with a margin below the measured value; a drop is a defect, a rise means the threshold may
  be ratcheted up by the tester with the evidence.

## 7. Running per persona

Each persona uses its own port so servers never collide: ML 5181, backend 5182, UI 5183, tester 5184.

```
cd web
PORT=5184 npm run test:e2e                      # e2e on your port (starts the dev server itself)
PORT=5184 E2E_TARGET=preview npm run test:e2e   # against the production build (run npm run build first)
npm test                                        # unit + dom
npm run test:browser                            # real WebGPU in vitest (uses PORT+1000)
npm run test:harness -- tests/harness           # accuracy / tracking / ball scoring
VBT_CHROME=/path/to/chrome npm run test:e2e     # alternative Chrome
```

Perf numbers (`ms/frame`, overlay p95) are only comparable on the same machine with nothing else running; the report
records machine, browser build and load. A different machine changes the budget, not the correctness thresholds.

Harness scoring CLI (task 3): `node tests/tools/score.ts --preds "label=<bench.json>[@0.4],..." [--frames static|run|all] [--target fused|R|V] [--jitter label=file] [--out summary.json]`
(Node 22 type stripping) prints the 06-style tables. Reference data is found through `VBT_BAKEOFF_DIR` and `VBT_FRAMES_DIR`.

Cross-browser: `PLAYWRIGHT_BROWSERS_PATH=<scratch>/pw-browsers PORT=5184 npx playwright test -c tests/playwright.cross.config.ts`
runs the `@cross`-tagged tests on WebKit headless and Firefox headed (a window opens). A missing browser is reported as
SKIPPED; `VBT_REQUIRE_CROSS=1` turns that into a failure (use it for the M3 acceptance run). Reports go to
`test-results/cross/` and `playwright-report/cross/` (inside the directories git and Biome already ignore). Findings so far (M0 tree): both browsers are cross-origin isolated
with a real adapter (WebKit vendor `apple`, Firefox empty vendor), WebCodecs and rVFC present; the rVFC frame-table
rule recovers the right frame in all three browsers, but Firefox 157 reports the seek target rather than the frame PTS
in `mediaTime`, so the player must keep using the `lastIndexWhere(pts <= mediaTime + 1e-4)` rule and never compare
`mediaTime` to a PTS for equality. Headed Firefox needs a live desktop session: one run took 18 minutes (14 passed) while the
machine was idle, the same run takes about 15 seconds when attended, so give it a timeout and do not run it unattended in CI
without a virtual display.

## 8. Manual checks (real devices; not automatable here)

1. iPhone (iOS 26/27) Safari: open a 10-minute clip, watch memory and tab survival, JSPI ORT flavour (probe open item 1).
2. Android Chrome (Mali/Adreno): tier selection, `webgpu-lite`, thermal behaviour over a 2-minute clip.
3. Windows Chrome and Firefox: adapter detection, `shader-f16` presence, fp32 tier.
4. Real Safari (macOS and iOS) and release Firefox: codec rows from the probe (HEVC, AV1, VP9).
5. iPhone Dolby Vision clip: base-layer HEVC retry (D1) decodes, or D2 error text is shown.
6. Screen reader pass (VoiceOver) on upload -> results; reduced-motion and 200 % zoom.
7. Install as PWA, go offline, reopen.
8. Visual QA of overlays on sand (beach) and a dark gym frame: contrast, glow, L/R colours.

## 9. Defect reporting

Defects are filed in the tester progress file as `DEFECT: <owner> — <steps> — <expected/actual>` with the command,
numbers and, when visual, a path to a Playwright trace or screenshot. A defect stays open until the owner reports a fix
and the tester's re-run is green.
